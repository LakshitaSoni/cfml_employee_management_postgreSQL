# People Hub – Employee Management System

A complete, database-backed employee management application written in **CFML** for **Adobe ColdFusion 2023** (also uses only CF 2025-compatible features) and **PostgreSQL**. Bootstrap 5 UI, no front-end build step, no hard-coded data.

| Area | What you get |
|---|---|
| **CRUD** | Create, read (searchable / sortable / filterable / paginated directory + profile page), update, delete-with-confirmation |
| **Dashboard** | Total / active employees, departments, recent hires, status split, top departments, latest hires |
| **UX** | Sidebar + top bar, avatars, status badges, toasts, loading states, empty states, live profile preview, responsive (desktop / tablet / mobile) |
| **Security** | Parameterized SQL only, server-side validation, output encoding, CSRF tokens, POST-only writes, CSP + security headers, generic error pages, credentials only from environment |

## 2. Database setup (PostgreSQL 12+)

You already have `admin_employee_management.employees` with `id`, `name`, `email`, `department`. The app also needs `phone`, `job_title`, `salary`, `joining_date`, `status`, `created_at`, `updated_at`.

### Create or upgrade the database schema

```bash
psql -U postgres -d admin_employee_management -f database/schema.sql
```

Optional sample data:

```bash
psql -U postgres -d admin_employee_management -f database/sample_data.sql
```

`schema.sql` should be **idempotent and non-destructive**: it only adds missing columns and indexes, never drops or rewrites existing data. Existing rows get `status = 'Active'`; new optional columns stay `NULL` until you edit the record.

It creates a `UNIQUE` index on `email`. If your table already contains duplicate emails, the index creation will fail. Identify and resolve duplicates before rerunning the index creation:

```sql
SELECT LOWER(email), COUNT(*)
FROM employees
GROUP BY LOWER(email)
HAVING COUNT(*) > 1;
```

The application should also enforce email uniqueness through server-side validation.

### PostgreSQL-compatible table structure

The final table should have the following structure:

| Column | Type | Notes |
|---|---|---|
| id | INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY | Existing or new primary key |
| name | VARCHAR(100) NOT NULL | Existing |
| email | VARCHAR(254) NOT NULL, UNIQUE | Existing + unique index |
| phone | VARCHAR(30) NULL | New |
| department | VARCHAR(100) NOT NULL | Existing |
| job_title | VARCHAR(100) NULL | New |
| salary | NUMERIC(12,2) NULL | New |
| joining_date | DATE NULL | New |
| status | VARCHAR(20) NOT NULL DEFAULT 'Active' | New; restricted using CHECK |
| created_at | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | New |
| updated_at | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | New |

The `status` column should have this constraint:

```sql
CHECK (status IN ('Active', 'On Leave', 'Inactive'))
```

For automatic updates to `updated_at`, use a PostgreSQL trigger or update the timestamp explicitly in the application's UPDATE statements.

### Create a least-privilege PostgreSQL user

Do not use the PostgreSQL superuser account for the application.

```sql
CREATE ROLE emp_app WITH LOGIN PASSWORD 'a-strong-password';

GRANT CONNECT ON DATABASE admin_employee_management TO emp_app;

GRANT USAGE ON SCHEMA public TO emp_app;

GRANT SELECT, INSERT, UPDATE, DELETE
ON TABLE employees
TO emp_app;

GRANT USAGE, SELECT
ON SEQUENCE employees_id_seq
TO emp_app;
```

If the sequence has a different name, identify it using:

```sql
SELECT pg_get_serial_sequence('employees', 'id');
```

The application database user should have only the permissions required to operate the application.

## 3. Configure the database connection (no credentials in source)

Pick **one** of the two options.

### Option A – Environment variables / `.env` (default)

Copy the example file:

```bash
cp .env.example .env
```

Edit `.env`:

```ini
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=admin_employee_management
DB_USER=emp_app
DB_PASSWORD=your-password
DB_DRIVER=PostgreSQL
APP_ENV=production
APP_CURRENCY=INR
```

Real OS environment variables take precedence over `.env` (use these in production / containers).

When `DB_HOST` and `DB_USER` are set, `Application.cfc` defines a per-application datasource named `admin_employee_management` using the PostgreSQL JDBC driver.

PostgreSQL uses port `5432` by default.

The PostgreSQL JDBC driver must be available to ColdFusion. Use the PostgreSQL JDBC driver compatible with your ColdFusion JVM and configure it through ColdFusion's datasource configuration or the application's supported datasource setup.

Values are read once per JVM – restart ColdFusion after changing them (or use `?reinit=1` with `APP_ENV=development`).

### Option B – Datasource in the ColdFusion Administrator

Leave `DB_HOST` / `DB_USER` empty and create a datasource instead:

1. ColdFusion Administrator → **Data & Services → Data Sources**.
2. **Data Source Name:** `admin_employee_management` (must match exactly; override with `DB_DATASOURCE` if you prefer another name).
3. **Driver:** PostgreSQL. Click **Add**.
4. Configure:
   - **Database:** `admin_employee_management`
   - **Server:** your PostgreSQL host
   - **Port:** `5432`
   - **Username:** `emp_app`
   - **Password:** your database password
5. If the PostgreSQL JDBC driver is not bundled with your ColdFusion installation, install/configure the compatible PostgreSQL JDBC driver.
6. Click **Submit** and confirm the datasource status is **OK**.

If neither option is configured (or PostgreSQL is down, or columns are missing), the app shows a clear **Database setup required** page (HTTP 503) – it never shows connection details. Technical detail goes to the `employee_app` ColdFusion log.

## 4. Run it locally

### With CommandBox (recommended)

Works with CommandBox 6.0 or newer for Adobe ColdFusion 2023.

```bash
cd cfml_employee_management_app
box server start
```

Uses `server.json`: Adobe ColdFusion 2023, web root `./public`, URL `http://127.0.0.1:8510`.

The first start downloads ColdFusion 2023 and a JRE (several hundred MB). Open:

http://127.0.0.1:8510/

Change the port in `server.json` if 8510 is taken.

Stop with:

```bash
box server stop
```

CommandBox's default CF Administrator password is `commandbox` – change it, and don't expose the admin outside localhost.

**Moving to ColdFusion 2025 later:** The code is intended to be CF 2025-compatible but has only been tested on CF 2023. Adobe CF 2025 needs CommandBox 6.2.0+ (it runs on Jakarta EE; older CommandBox fails with `NoClassDefFoundError: jakarta/servlet/Servlet`).

Change `cfengine` in `server.json` to `adobe@2025` (and add `"jvm": {"javaVersion": "openjdk21_jre"}`), then rerun `tests/e2e.sh`.

### On an existing ColdFusion 2023 / 2025 installation (IIS / Apache / Tomcat)

Create a site / virtual directory whose **document root is `<repo>/public`**, with ColdFusion handling `.cfm` / `.cfc`.

Keep the rest of the repository outside any served folder.

Set the environment variables at machine/service level (or put `.env` in the repository root) and restart the ColdFusion service.

Nothing else is required – the `/app` mapping is created by `Application.cfc` relative to its own location.

## 6. Security design

| Concern | Implementation |
|---|---|
| SQL injection | Every value bound via typed `queryExecute` parameters. The only interpolated SQL (ORDER BY column/direction) comes from fixed whitelists. LIKE wildcards in search are escaped. |
| XSS | All output through `encodeForHTML` / `encodeForHTMLAttribute` (`h()` / `ha()`); `<` and `>` rejected in text fields on input; strict CSP (`script-src 'self'`, no inline scripts). |
| CSRF | Per-session 256-bit token in every form, verified in constant time on every POST; `SameSite=Lax` + `HttpOnly` session cookie (`Secure` automatically on HTTPS). |
| HTTP methods | `save.cfm` / `delete.cfm` reject anything but POST; GET never changes data. |
| Validation | Server-side for every field (required, length, format, strict real-date check, numeric ranges, status whitelist, unique email – checked in the app and enforced by the database unique index; a race that trips the index is reported as a friendly field error). |
| Errors | `onError` logs the real error to `employee_app` and shows a generic page with a reference ID. No stack traces, SQL or config reach the browser. |
| Secrets | Only from OS environment / git-ignored `.env` outside the web root (or the CF Administrator). Nothing sensitive in source control. |
| Delete | Bootstrap confirmation dialog → POST + CSRF token. |

### Known limitation – no login screen

The brief did not ask for authentication, so none is included: **anyone who can reach the site can manage employees.**

Run it on a trusted network or behind your SSO / reverse-proxy authentication before exposing it, and consider adding roles + audit logging as a next step. Salary data is sensitive.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| "Database setup required – could not connect" | PostgreSQL running? `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD` correct? Check the `employee_app` log (CF Administrator → Debugging & Logging → Log Files). |
| "Missing columns" | Run `database/schema.sql` using `psql`. |
| `No suitable driver available` | Verify the PostgreSQL JDBC driver is installed and configured correctly in ColdFusion. Restart ColdFusion after installing it. |
| `NoClassDefFoundError: jakarta/servlet/Servlet` on `box server start` | You switched `server.json` to CF 2025 on a CommandBox older than 6.2 – upgrade CommandBox or use `adobe@2023`. |
| PostgreSQL connection refused | Verify PostgreSQL is running, listening on port `5432`, and accepting connections from the application host. |
| PostgreSQL authentication failed | Verify the `emp_app` role, password, `pg_hba.conf`, and database privileges. |
| Changed `.env` but nothing happened | Environment is cached per JVM – restart CF, or open any page with `?reinit=1` when `APP_ENV=development`. |
| Port 8510 in use | Change `web.http.port` in `server.json`. |
